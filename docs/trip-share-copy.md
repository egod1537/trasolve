# 공유 여행을 내 지도로 복사

## API

`POST /api/shared-trips/:token/copy`는 현재 로그인한 사용자의 계정에 공유 여행의 독립 복사본을 만든다. 요청 본문은 없으며 성공 응답은 `201`과 다음 최소 정보만 반환한다.

```json
{
  "tripId": "new-trip-id"
}
```

세션에서 확인한 내부 사용자 ID만 새 Trip의 소유자로 사용한다. 클라이언트가 소유자 ID를 보낼 수 있는 입력은 제공하지 않는다. 익명 요청은 `401`, 형식이 잘못됐거나 비활성화·삭제된 공유 토큰은 `404`다. 오류는 공통 `{ "error": { "code", "message" } }` 형태다.

복사 POST는 `Origin`과 요청 호스트가 일치해야 하고, `Sec-Fetch-Site`가 있으면 `same-origin`이어야 한다. 세션 쿠키의 기존 `SameSite=Lax` 정책과 함께 교차 출처 변경 요청을 거부한다. 요청 본문은 허용하지 않아 업로드 크기는 0바이트로 제한한다. 복사할 데이터 크기는 기존 Trip 스키마의 일자·장소·경로 상한과 서버 요청 제한을 그대로 따른다. 별도 다중 인스턴스 rate limiter는 현재 서비스에 없으므로 이 엔드포인트만의 메모리 기반 제한은 추가하지 않았다.

## 복사 필드 정책

원본의 `title`, `startDate`, `endDate`, 일자, 장소, 순서, 체류 시간, 메모, 스타일, 레이어 순서와 경로 표현을 기존 `TripInput` 범위에서 보존한다. 제목은 원본과 동일하게 유지한다.

복사본은 기존 `TripController.createTrip`으로 생성한다. 다음 값은 복사하지 않는다.

- 원본 `id`, `userId`, revision, 생성·수정 시각
- 원본 owner 응답, attribution, 공유 토큰과 공유 설정
- 일자·장소·폴리라인의 내부 ID

생성 경로가 새 Trip ID와 모든 내부 ID를 발급하고 폴리라인 및 레이어 참조를 새 ID로 치환한다. 새 Trip에는 공유 레코드가 없으므로 기본 비공개다. 복사본은 원본을 참조하지 않으며 이후 원본 수정·삭제·공유 해제의 영향을 받지 않는다.

## 로그인 후 복귀와 열기

공유 페이지 GET과 읽기 전용 지도는 로그인 없이 유지된다. 로그아웃 상태에서 `내 지도로 복사`를 누르면 기존 OAuth 시작 흐름에 현재 `/share/:token` 경로를 `returnTo`로 전달한다. OAuth 완료 후 같은 공유 페이지로 돌아오며 자동으로 POST하지 않는다. 사용자가 로그인된 버튼을 다시 눌러 실행 의사를 명확히 확인해야 복사가 한 번 시작된다.

복사 중에는 클라이언트 요청 참조와 버튼 loading 상태로 재클릭을 막는다. 성공하면 `/map?trip=:tripId`로 이동하고 지도 작업 화면이 해당 사용자의 목록에서 정확한 Trip을 선택한다. 소유하지 않거나 잘못된 ID이면 기존 여행 선택 화면을 유지한다.

## 오류, 재시도, 경합

복사 조회와 복사 진행 상태는 분리한다. POST가 실패해도 원본 읽기 전용 지도는 유지하며 사용자가 다시 시도할 수 있는 오류를 표시한다. `401`은 일반 복사 실패 대신 로그인 흐름으로 보낸다. 클라이언트는 네트워크 결과가 불명확한 요청을 자동 재시도하지 않는다.

서버는 동일 프로세스에서 같은 사용자와 공유 토큰으로 동시에 들어온 요청을 하나의 진행 중 작업으로 합쳐 같은 `tripId`를 반환한다. 첫 작업이 끝난 뒤 사용자가 새로 명시적으로 요청하면 별도의 복사본을 만든다.

복사 요청은 처리 시점마다 활성 공유 레코드와 삭제되지 않은 원본을 다시 조회한다. 조회 전에 공유가 해제되면 `404`이며 복사본은 생기지 않는다. 활성 상태와 원본을 확인한 뒤 공유 해제가 경합하면 이미 승인된 복사는 완료될 수 있다. 이 시점에 생성된 복사본도 원본과 독립적이다.

공동 편집, 권한 위임, 원본과의 동기화나 병합은 이 흐름에 포함하지 않는다.
